# Bazaar backend integration contract

Status: integration specification and browser adapter, **not a deployed service**. The owner confirmed no backend exists yet. Do not enable production checkout or uploads by pointing the browser at a placeholder URL. No billing upgrade, hosting deployment, or Firestore rules deployment is included.

## Boundary

`src/engine/bazaar/orderWorkflow.js` contains the transport-independent order and stock transaction logic. A production adapter must implement atomic Firestore Admin SDK transactions, including transaction retries and read-before-write ordering. `tests/bazaar-test-server.mjs` is guarded for a local demo emulator only; it is not a production server.

`VITE_BAZAAR_API_URL` is an HTTPS service base URL. It is public configuration, never a signing key. The browser reports missing/invalid configuration and disables checkout. A configured URL does not prove endpoint health; network errors preserve the cart and the retry key.

Seller endpoints must verify Firebase ID tokens with a trusted verifier, then derive seller identity from the verified token. Never accept a caller-supplied UID as authentication. Check the shop's actual owner and relevant Bazaar license authorization on the server. The pure transaction core checks ownership; it is not a Firebase token verifier or license verifier.

## Ordering

- `POST /submit`: validate and size-limit guest JSON, protect against abuse/rate flooding, run `submitOrder`. Recalculate from current private catalog and icon library; ignore client price and artwork claims. Atomically commit order, tracking capability, and idempotency result.
- `POST /transition`: verified seller, action accept/prepare/ready/collect/cancel; call `transitionOrder`.
- `POST /allocate`, `POST /adjust`: verified seller, validated payload, call the corresponding transaction core.
- Enforce application-specific queue limits and available payment methods before production deployment. The existing standalone queue helper is not yet integrated into the trusted intake transaction. Financial/payment flows need a trusted adapter too.
- Configure restricted CORS, request limits, structured safe errors, server timestamps, and monitoring that excludes customer details, ID tokens and tracking capabilities. Consider App Check plus rate limiting; neither makes a client price authoritative.

## Icon library

All endpoints require a verified seller token:

| Endpoint | Request | Response |
|---|---|---|
| GET `/icons` | No arbitrary owner parameter | `{ icons: [...] }` for the authenticated seller only |
| POST `/icons` | Multipart `image` (PNG) and `name` | New immutable asset metadata |
| PATCH `/icons/:id` | Name, archive flag, fulfillment mode, inventory SKU or components | Updated metadata |

Metadata lives under `shops/shop_<verified UID>/icons/<generated ID>`. Storage paths must be generated by the server within the same seller namespace. Do not honor client filesystem paths, remote fetch URLs, ownership fields or object identifiers belonging to another seller. Return stable HTTPS image and thumbnail URLs; URLs embedded in historical orders must not expire. Retain referenced assets when archiving.

Re-decode and validate uploads on the server even though the browser validates them. Limit input/output bytes to 2 MB, dimensions to 2048 pixels, reject corrupt/unsupported files, and encode raster output with metadata removed. The browser rejects active/external SVG content and converts accepted SVG to PNG; never persist or serve active uploaded SVG. Serve fixed image MIME types with nosniff and a restrictive storage policy. No base64 image fields in Firestore.

Suggested metadata: `id`, `name`, `imageUrl`, `thumbnailUrl`, `storagePath`, `width`, `height`, `mimeType`, `archived`, `fulfillmentMode`, `inventorySku`, `components`, timestamps and server-owned owner identity. Return public artwork fields only in product projections. Internal stock, costs and supplier data remain private.

- `artwork_only`: no purchasable physical item, no stock created.
- `preprinted`: exact existing `inventorySku`; verify the document belongs to the seller.
- `made_to_order`: explicit nonempty components list, each with an existing `component_key` and positive integer `required_qty` per icon.

Archive must prevent new selection across every product using that library entry. Republish affected public projections, while keeping old order snapshots and assets intact. Trusted checkout already resolves library references again and rejects an archived/missing selected icon.

No provider has been chosen or provisioned. Do not assume Firebase Storage or a Cloud Function can be enabled under the current account's plan. Provider selection, billing implications and production security rules require a separate reviewed deployment decision.
